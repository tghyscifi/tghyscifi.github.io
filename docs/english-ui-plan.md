# 界面级英文版实施计划

## 范围

- 中文地址保持不变，英文界面使用 `/en/`。
- 翻译站点与页面标题、博文标题、分类标签的显示名称、导航、按钮、提示、日期和小说信息卡字段。
- 博文、小说与动态正文保持中文，不复制维护两套长文本。
- 暂不生成英文 RSS；英文界面的订阅入口仍指向现有中文订阅源。
- 控件复用 `themes/meow/languages/` 原生词典和 Hexo 国际化接口；标题映射及构建配置独立维护，不另建控件翻译体系。
- 仅提交本地 Git 版本，本轮不推送或部署。

## 实施阶段

1. **计划检查点**：记录本计划及范围，形成可回退的起点。
2. **双语构建与标题**：共用中文内容和主题，通过英文短文案目录生成临时英文内容与配置；分别构建、合并静态产物，隔离构建缓存；提供对应页面的语言切换。
3. **界面控件**：补齐英文词典、小说信息卡、下载页、音乐工具、日期、评论和搜索等控件文案，说明中文正文状态。
4. **验证与交付**：验证中文路由、英文标题和控件、长文本未改动、RSS 未增加、搜索与评论路径、移动端语言切换；补充使用与回退说明。

每个阶段完成后检查差异与构建结果，单独提交 Git；修正也以独立提交记录。共享工作区由主代理统一提交，子代理不执行 Git 写入。

## 分工

- 主代理：构建脚本、语言路由与切换、阶段集成、验证及 Git 检查点。
- GPT-6.1-Sol（低推理）子代理 A：英文短文案目录、标题与主题配置覆盖、主题英文词典。
- GPT-6.1-Sol（低推理）子代理 B：下载页、音乐工具、动态日期等控件的国际化接入。

用户已选择本轮由子代理直接翻译短文案。优先复用现有英文词典；链接、代码、占位符和专名保持稳定。

## 验收与回退

- 首页、文章、归档、分类、标签、关于、动态、友链、留言、APP 和音乐页面的语言切换可用。
- `/en/` 下标题及控件为英文，原始长文本保持中文；切换语言优先停留在对应页面。
- 不生成 `/en/atom.xml`、`/en/essay/atom.xml`；中文订阅不改格式及条目标识。
- 加密文章不因英文界面暴露明文，搜索与订阅维持保护。
- 阶段提交均可使用 `git revert <提交号>` 回退；避免以硬重置丢弃后续修改。

## 原生语言入口的结论

`themes/meow/languages/` 提供静态语言词典，导航、工具栏、搜索和文章信息已通过 Hexo 的 `__()`、`_p()` 读取。复用该机制可直接承担控件翻译；页面语言由配置和 `lang` 决定。对应页面的切换按钮、标题映射以及自定义 JavaScript 提示在此基础上接入。

- 控件统一维护在原生 `en.yml`、`zh-CN.yml`，前端消息由同一份词典导出。
- `locales/en.yml` 仅维护标题、分类标签显示名与英文主题配置。
- 每次构建读取同一份中文源内容，使用独立缓存生成中文和英文界面，合并后发布。
- 保留分类标签原始路径；英文站切换语言会回到同一篇文章或同一个页面。

## 使用及维护

```bash
npm ci
npm run build
npm run check:i18n
npm run preview
```

访问 `http://localhost:4000/` 和 `http://localhost:4000/en/`。`npm run server` 保留中文内容的实时开发预览；双语静态预览在修改后重新构建。

新增页面或博文时，在 `locales/en.yml` 补充对应标题；新增控件时同步两份原生语言词典，保持变量占位符一致。

回退整个功能时按 Git 记录从新到旧依次撤销本轮提交。回退源码后执行 `npm run clean`，再按当时版本的构建命令重新生成，以清理旧的 `/en/` 静态产物。
