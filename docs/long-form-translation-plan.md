# 英文长文本翻译计划

日期：2026-10-18。起点：`d8548da`。

本文件规划下一阶段；本次只记录计划，不翻译正文、不修改构建行为、不推送或部署。

## 目标与边界

- 在现有 `/en/` 界面中逐步提供小说、动态、站点介绍及其他博文的英文正文，中文地址、正文与菜单保持原样。
- 沿用对应页面的语言切换和现有评论线程，不建立两套独立文章身份。
- 英文 RSS 继续暂缓；现有中文 RSS 的内容、日期与条目标识保持稳定。
- 保留中文原作及其旧稿／弃稿标记。翻译不代替改写、补全情节或修订世界观。
- 未完成的译文留在工作目录；公开英文页面继续显示中文回退内容并明确标注，支持逐篇上线。

## 当前内容与接入点

按当前源文件统计正文中的汉字数，不包含 YAML 元数据；该数字不是翻译后的英文词数或工时报价。

其他独立页面、下载说明、图片内文字和图片说明在清点阶段逐项登记，避免仅翻译小说正文而留下入口与摘要的中文。功能测试页以验证加密和特殊格式为主，内容翻译排在最后。

现有实现的限制：

1. `tools/build-bilingual.cjs` 的中英文构建读取同一份 `source/`，目前只覆盖英文配置和标题。
2. `scripts/ui-i18n.js` 不替换正文，且明确跳过正文中的链接改写。
3. `themes/meow/layout/pages/post/posts.pug` 将正文 `lang` 写死为 `zh-CN`，`components/language-note.pug` 对所有英文页面统一提示正文为中文。
4. 首页摘要可能来自显式 `excerpt`，也可能从正文截取；译文必须同步覆盖摘要，不能只更换全文。
5. 动态存于 `source/_data/essay.yml`，没有独立 ID；现有 RSS 使用发表时间构造稳定标识。
6. `tools/check-bilingual.cjs` 目前要求中英文正文完全相同；接入译文时需要改为按翻译状态分别验收。

## 推荐的内容组织

中文 `source/` 继续作为原作来源。译文放在 Hexo 源目录之外，避免草稿被自动发布、被搜索收录或在中文归档中重复出现。

拟新增以下结构，具体文件在实施阶段创建：

```text
translations/
  manifest.yml                 # 原文标识、译文状态、原文摘要值和术语表版本
  glossary.yml                 # 人名、地名、组织、科技与政治术语的统一译法
  style-guide.md               # 叙述、对白、标点、方言、注释等约定
  en/
    posts/p01.md               # 一篇原作对应一份英文 Markdown
    posts/...
    pages/...
    essay/2026-10-01-21-16-46.md
```

- 博文以现有固定路由作为映射依据，不依赖中文文件名或标题。
- 动态以与现有 RSS 一致的发表时间标识关联；检查重复时间、时区和缺失映射。不能用数组下标关联，新增或重排动态不会串译。若日后修改原动态日期，单独处理映射迁移。
- 译文只覆盖允许翻译的字段，例如标题、正文、摘要和说明；发布时间、固定链接、资源路径、密码、分类标签身份等从中文继承。
- 每篇记录原文内容摘要值及所用术语表版本。原作变化后标记 `stale`，列出需要同步的段落，不静默覆盖或删除人工修订。
- 状态建议为 `todo → draft → reviewed → approved`，原文变更另加 `stale` 标记。默认仅 `approved` 且与原文版本匹配的译文进入正式构建；其他状态继续回退中文。单独的本地审稿模式可以查看草稿，但不进入发布流程。
- 每篇小说先整篇达到可发布状态再替换公开正文，避免一章内中英文混排；动态可逐条发布。

## 翻译原则与协作

建议默认采用自然、忠实的美式英语，保留叙述节奏、人物差异、粗口强度和作者立场，不额外美化旧稿。不因未选择拼写习惯而阻塞草稿准备。

- 先扫描所有小说和中心导航，提取术语及角色关系，再翻译片段；跨篇共享一个术语表。
- 《率月纪元》、溯月馆、瞳观幻域，以及人名、率子、奇术、量神经元、政委和各组织名称先给出候选译法，未定项标注待作者定稿，不凭空造设定。证辰／证·辰等不同写法及人物别名建立对应关系；现有英文标题也作为暂定译名一并复核。
- 对武汉方言等地方语言，优先用措辞和节奏体现口音、语体差异，避免机械映射为某个英语地区的方言；具体尺度通过样稿确定。
- 对梗、双关、影射及反讽，提供译法与一句说明；必要时给出两种候选，由作者决定。译者注限于帮助理解，不插入正文解释原作没有说明的情节。
- 小说按场景或章节切分翻译，边界不打断对白、脚注或连续论述；每批附带人物表、术语表、前文梗概和上一批衔接段落。
- 动态保留随手记录的语气；教程保持步骤、命令和链接可操作；评论文章保持论证关系、限定条件和语气强度。

分工建议：

| 角色 | 工作 |
| --- | --- |
| 主代理 | 清点、术语表和样稿整合、构建接入、格式保护、质量抽查、问题汇总及 Git 版本 |
| Sol 6.1（低）翻译子代理 | 按定稿术语和风格生成草稿；同一批次尽量完成连续场景，列出不确定项 |
| 独立复核子代理 | 对照原文检查遗漏、增译、数值、否定、因果、说话人和术语，不只润色英文 |
| 作者 | 决定专名及文学处理，核对高风险歧义、试译文风和对外发布的最终文本 |

沿用当前可用的子代理即可准备草稿，不要求作者注册翻译服务或提供 API 密钥。若未来主动选择外部翻译服务，再另行讨论费用和接入，不作为本计划前提。

## 阶段与交付物

### 1. 清点与术语、风格准备

- 建立待译清单，列出正文、摘要、图片说明、特殊标签、加密状态和源版本。
- 生成首版术语表、人物表、风格约定，以及集中给作者处理的选择题清单。
- 人工决策尚未返回时，可以继续内容清点、格式分析和无争议的技术准备。
- 交付：待译清单、术语候选与统一审阅清单。单独记录 Git 版本。

### 2. 代表性片段试译

- 从《神谕之初》选取一个含对白、讽刺和科技叙述的完整片段；从《黄鹤楼，宜逢故人》选取一个含方言和专名的完整片段。各约 500–800 个汉字，保留必要上下文。
- 另用《弦外杂音》开篇三个段落检查历史叙述、长句和政治术语，避免用口语对白的译法统一所有章节。
- 再选两条动态，一条日常口语、一条观点或创作记录，验证语体差异。
- 提交中英对照、关键译法说明和少量可选表达。只要求作者集中判断术语、语气与误解，不把整份逐句初校转交给作者。
- 交付：样稿和修订后的术语／风格约定；样稿不直接替换公开正文。

### 3. 建立可逐篇发布的构建支持

- 为英文构建创建独立临时源目录：复制中文内容与资源，按状态覆盖已完成的译文，再交给 Hexo 渲染和加密；中文构建仍读取原目录。
- 译文覆盖发生在渲染、加密、搜索索引与摘要生成之前；禁止对最终 HTML 粗暴替换正文。
- 新增按篇／按条翻译状态读取，调整正文 `lang` 与语言提示；已译、未译、原文更新待同步分别显示恰当说明。
- 英文正文中的站内链接指向对应英文入口；未译目标继续显示中文回退提示。保留图片、下载、外链和中文原文引用的正确目标。
- 检查目录锚点、跨章节跳转和显式锚点，避免标题翻译后链接失效。
- 动态仅在英文临时数据中替换匹配条目的 `content`，继承日期、作者、图片和顺序，中文动态及 RSS 生成链路不变。
- 首页、小说中心导航、搜索摘要、分享描述、阅读时长与内容语言同步；正文中的全角缩进和主题首行缩进按实际语言处理。
- 交付：有译文／无译文／过期译文三种本地预览，以及可重复执行的检查。此阶段可用测试夹具验证，不提前发布文学草稿。

技术依据：[Hexo 数据文件](https://hexo.io/docs/data-files)支持通过 `_data` 载入结构化内容；[Hexo Filter API](https://hexo.io/api/filter)明确区分渲染前与生成前的处理时点。本计划优先选择临时源覆盖，降低正文接入与加密、搜索处理次序相互影响的风险。

### 4. 第一批完整内容

- 先完成关于页面、小说中心导航和 12 条动态，使英文读者能理解站点与作品入口。
- 再完成《神谕之初》整篇，以试译确定的规则跑完一次长篇流程；若作者希望优先展示其他篇目，调整顺序即可。
- 每篇经过草稿、对照复核、文学修订和作者集中定稿；逐篇提交，逐篇启用。
- 交付：第一批可完整阅读的英文页面和本次疑难译法记录。

### 5. 扩展至其余内容与日常维护

- 小说按前传、正传、后传的关联顺序推进；保留旧稿／弃稿标记及写作时期的差异。影评、教程和工具说明可在规则稳定后并行处理。
- 每批限制在能完整复核的篇幅；不能仅凭自动回译认定文学质量通过。
- 原文新增或更新后，自动列出缺译和过期内容，只重做受影响部分；保留人工定稿段落。
- 每篇／每批使用独立 Git 提交。推送和部署由作者决定时间，操作可由主代理代办。

## 哪些需要作者人工完成

### 需要作者作出判断

1. **专名定稿**：系列名、笔名、站名、角色与核心设定的英文写法；已有正式译名或旧设定表时提供即可，没有则由主代理先整理候选。
2. **样稿文风选择**：确认小说对白、粗口、方言、梗和注释的尺度。先确认代表性片段，后续沿用，避免每篇重复选择。
3. **作者意图澄清**：处理少量无法从上下文确定的双关、伏笔、指代和世界观歧义；区分原作故意保留的含混与真实笔误。
4. **文学成稿与发布判断**：建议对首篇完整小说做一次通读，后续重点看标出的争议段落；逐章完整精读属于推荐的质量投入，不是技术上必须完成的步骤。确认哪些译文可以对外展示，以及何时推送、部署。

不会要求作者手动拆 Markdown、复制粘贴所有译文、修改 YAML 映射、安装新工具、检查每个链接或逐行审阅机器初稿。作者只需在集中审阅清单中回复选择或修改意见，主代理负责落盘和接入。

### 可选提供的材料

- 已经使用过的英文专名、设定集、人物关系表、喜欢的英译风格样例。
- 希望优先翻译的篇目，或应暂缓翻译、准备重写的旧稿。
- 如果希望完整精读所有英文成稿，可自行安排或邀请英文母语审校；并非接入英文正文所必需的账号或工具操作。

## 验收标准

- 中文正文、导航、固定路由及动态顺序保持不变，中文 RSS 条目标识稳定，英文 RSS 仍不生成。
- 已完成译文在英文全文、摘要、中心导航和搜索中一致；未完成、过期和草稿不会被误标为已定稿英文。
- 正文实际语言、提示与排版一致；语言切换回到同一作品，评论仍使用原线程。
- 标题和段落、对白轮次、人物名、数值单位、否定条件、链接、图片、脚注、标签和代码经结构检查与对照复核。
- 加密内容继续受保护，英文搜索、摘要和临时产物的发布清单不暴露受保护明文。
- 桌面与手机检查英文长段落、长标题、引用、目录和跳转；自动检查覆盖已译、未译、过期、更新原文、动态插入与重排等情况。
- 每一批都有独立提交，可单独撤销译文或接入逻辑；撤销后重新构建，清除旧产物。

下一步建议：先建立术语候选和代表性试译审阅清单，再进入整篇翻译。
