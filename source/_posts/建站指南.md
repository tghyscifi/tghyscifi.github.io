## 主题配置

我使用的主题模板作者 [chanwj (小橘猫)](https://github.com/chanwj) 提供了详细的配置指导文档，可以直接参考：[MEOW - 简洁可爱的响应式Hexo主题🐱](https://meow.jumaoo.top/)

### 安装主题

首先进入博客项目根目录（以我本地文件为例：`D:\Hexo\blog`）：

```Bash
cd blog
```

然后将所需主题的仓库 clone 到本地目录（以 [MEOW](https://meow.jumaoo.top/) 为例）：

```Bash
git clone -b main https://github.com/chanwj/hexo-theme-meow.git themes/meow
```

或者手动下载项目文件再解压到该目录。

总之，要确保主题文件安装在 `/themes/meow` 下，这里的 `meow` 为你安装的主题名称，可自行替换。

此外，部分主题需要安装额外的依赖项，只需按主题作者给出的安装文档在根目录下执行操作即可。以 [MEOW](https://meow.jumaoo.top/) 为例：

```Bash
npm install hexo-renderer-pug --save
npm install hexo-renderer-stylus --save
```

这里的 `npm install [插件名] --save` 指令是 [Hexo](https://hexo.io/zh-cn/) 框架下安装[插件](https://hexo.io/plugins/)的常用操作，会频繁用到。

### 应用主题

安装完成后，在博客根目录下找到 `_config.yml` 配置文件，找到并编辑 `theme` 项：

```YAML
theme: meow
```

这里填你之前定义的主题名称就可以了。

### 配置主题

此时博客项目中有两个配置文件，分别是 `/_config.yml` 和 `/themes/meow/_config.yml`，即博客本体与主题的配置文件。

根据 Hexo [官方文档](https://hexo.io/zh-cn/docs/configuration#%E4%BD%BF%E7%94%A8%E4%BB%A3%E6%9B%BF%E4%B8%BB%E9%A2%98%E9%85%8D%E7%BD%AE%E6%96%87%E4%BB%B6)与模板作者的[配置建议](https://meow.jumaoo.top/posts/16777e4b#%E9%85%8D%E7%BD%AE%E5%BB%BA%E8%AE%AE)，为便于后续更新主题，应当将 `/themes/meow/_config.yml` 复制到根目录下并命名为 `_config.meow.yml`，之后仅将 `/_config.meow.yml` 作为主题配置文件。

[HexoHub](https://github.com/forever218/HexoHub) 提供了 `_config.yml` 中部分配置项的 GUI，但真正的 DIY 还是需要亲手编辑两个配置文件的每一项，过程类似于填表。每个配置项的作用与可选值见官方文档：

- 本体配置（`_config.yml`）：[配置 | Hexo](https://hexo.io/zh-cn/docs/configuration)
- 主题配置（`_config.meow.yml`）：[Meow 主题文档 - 主题配置 | MEOW](https://meow.jumaoo.top/posts/16777e4b/)

关于 YAML 文件格式的语法，可以参考：[YAML 入门教程 | 菜鸟教程](https://www.runoob.com/w3cnote/yaml-intro.html)

## 网页部署

网页部署包括本地部署（`localhost`）与 GitHub Pages 部署。由于博主未尝试服务器部署，该部分请参考[官方文档](https://hexo.io/zh-cn/docs/one-command-deployment)。

### 本地部署

用于在本地测试博客网页。

在博客根目录下依次执行以下操作：

```Bash
hexo clean
hexo generate
hexo deploy
hexo server
```

然后你的浏览器就会自动打开一个 `localhost` 页面，里面就是你的博客网页。

如果使用 [HexoHub](https://github.com/forever218/HexoHub)，那么只需依次点击"清理"→"生成"→"部署"→"启动服务器"，并在下一次测试前点击"关闭服务器"。

注意：这里 `hexo deploy` 能将生成的 `/public` 网页文件部署到本地服务器的前提，是 `_config.yml` 中 `deploy` 项设置保持默认。如果 `deploy` 中配置了 `git`，那么该指令就会触发到 GitHub 的部署。

### GitHub Pages 部署

使用 GitHub Page 的好处就是不用买服务器和域名，但也带来了一些问题：

- GitHub Pages 服务不稳定，在特定时间可能会抽风，导致 Update 与 Deploy 异常。如遇该情况请关注 [GitHub Status](https://www.githubstatus.com/) 的最新动态，并耐心等待官方修复。
- GitHub Pages 的默认 Build 可能并不适用于某些博客项目，需要自行配置 GitHub Actions 完成构建与部署过程。参考 Hexo 的官方指南：[在 GitHub Pages 上部署 Hexo | Hexo](https://hexo.io/zh-cn/docs/github-pages)

根据我的惨痛教训，整理得到以下针对 Hexo 博客的 GitHub Pages 部署流程：

1. 创建 GitHub Pages 仓库：官方文档：[GitHub 页面快速入门 - GitHub 文档](https://docs.github.com/zh/pages/quickstart)
2. 在博客根目录下初始化 Git 并配置信息：

   ```Bash
   git init

   git config user.name "用户名"
   git config user.email "用户email"
   git remote set-url origin 仓库的git链接
   ```

3. 在博客根目录下新建文件 `.gitignore` 并填写：

   ```
   public/
   ```

4. 将本地博客项目文件推送到仓库（如使用 [HexoHub](https://github.com/forever218/HexoHub) 则可以直接点击"推送"，有时可能需要手动 `git push`）：

   ```Bash
   git add .
   git commit -m Update
   git push -u origin master
   ```

5. 配置 GitHub Actions
   现在 GitHub 仓库中会显示构建失败，因为 GitHub 的默认配置是用 `Jekyll` 构建，但我们用的是 `Hexo`，所以需要到仓库的 `Setting` → `Pages` 页面，将 `Build and deployment` 的选项改为 `GitHub Actions`，然后按照[在 GitHub Pages 上部署 Hexo | Hexo](https://hexo.io/zh-cn/docs/github-pages) 的指引，新建并填写工作流文件 `/.github/workflows/pages.yml`。我用的是 AI 改良后的工作流文件：

   ```YAML
   name: Pages

   on:
     push:
       branches:
         - master
     workflow_dispatch:

   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
           with:
             token: ${{ secrets.GITHUB_TOKEN }}
             submodules: recursive
         - name: Use Node.js 26
           uses: actions/setup-node@v4
           with:
             node-version: "26.3.1"
         - name: Cache NPM dependencies
           uses: actions/cache@v4
           with:
             path: node_modules
             key: ${{ runner.OS }}-npm-cache-${{ hashFiles('**/package-lock.json') }}
             restore-keys: |
               ${{ runner.OS }}-npm-cache
         - name: Install Dependencies
           run: npm install
         - name: Build Hexo
           run: |
             npm install -g hexo-cli   # 关键：全局安装 hexo-cli
             hexo clean
             hexo generate             # 直接运行，不需要 npm run build
         - name: Upload Pages artifact
           uses: actions/upload-pages-artifact@v3
           with:
             path: ./public
     deploy:
       needs: build
       permissions:
         pages: write
         id-token: write
       environment:
         name: github-pages
         url: ${{ steps.deployment.outputs.page_url }}
       runs-on: ubuntu-latest
       steps:
         - name: Deploy to GitHub Pages
           id: deployment
           uses: actions/deploy-pages@v4
   ```

   注意：文件中 `Node.js` 与 `node_version` 这两处的版本号以本地开发环境的实际版本号为准，获取版本号：

   ```Bash
   node --version
   ```

6. 然后再次提交，这次应该就可以触发 `GitHub Actions` 的 `Build` 和 `Deploy` 进程。

{% note pink %}
部署过程中遇到任何问题，请将仓库 Actions 中的日志信息复制粘贴给 AI。
{% endnote $}

## 额外功能

如果使用 [MEOW](https://meow.jumaoo.top/) 主题，那么官方文档中已提供了增添与配置各种额外功能的详细说明。这里仅对[模板作者](https://github.com/chanwj)没有详细说明的功能作一些补充。

{% fold '点击展开评论功能说明' purple [status] %}
[MEOW](https://meow.jumaoo.top/) 的评论功能基于 [Waline](https://waline.js.org/)。官方提供了大量的方案选择，但其中满足需求的并不多。下面是我最终跑通的方案：

1. 编辑 `_config.meow.yml` 的相关项：

   ```YAML
   comment:
     enable: true
     display: true
     type: waline
     lazyload: true
     waline:
       server_url: 此处填写配置好的 waline 服务所在域名
       lang: zh-CN
       emoji:
         - 'https://registry.npmmirror.com/@waline/emojis/1.3.0/files/qq'
         - 'https://registry.npmmirror.com/@waline/emojis/1.3.0/files/tw-emoji'
       reaction:
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/2764-fe0f.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f92f.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f4a5.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1fae1.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f602.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f914.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f97a.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f6a8.png'
         - 'https://cdn.jsdelivr.net/npm/emoji-datasource-google@14.0.0/img/google/64/1f921.png'
       option:
         locale:
           placeholder: '欢迎评论～'
           reactionTitle: '点赞支持我吧！'
         commentSorting: 'hottest'
         requiredMeta: ['nick', 'mail']
   ```

   这里的 9 个 `reaction` 可以替换为自定义的 emoji 链接。
   重点是 `server_url` 项，配置该项需要下面的操作。

2. 获取一个域名
   推荐在[ClouDNS](https://www.cloudns.net/)获取一个免费的二级域名，形如 `xxx.yyy.zzz`，为方便这里简写为 `yourdomain`。
   注意：该网站对部分地区的申请请求有限制，建议使用梯子多换几个地区试试。

3. 在第三方平台配置 Waline 服务
   推荐在 [Railway](https://railway.com/) 部署你的 Waline 服务：[官方文档](https://waline.js.org/guide/deploy/railway.html)
   然而造化弄人的是，Railway 更新后，旧的文档有一些问题，需要一些额外操作：

   - 用[官方文档](https://waline.js.org/guide/deploy/railway.html)的按钮新建项目后，直接部署会失败，需要手动将 `Postgres` 中的环境变量值复制到 `app` 的环境变量列表中，再执行部署
   - 新的 Railway GUI 没有单独的 Query 列，而是转移到了 `Postgres` 的 `Database` 选项卡的搜索框，将[官方文档](https://waline.js.org/guide/deploy/railway.html)中的 SQL 代码复制粘贴到搜索框内执行就可以了
   - 配置服务域名，需要在 `app` 的 `Deployments` 选项卡下新建 `custom domain`，填入 `comment.yourdomain` 即可触发验证
   - 验证域名：按照指引信息在[ClouDNS](https://www.cloudns.net/)中添加两条解析记录（通常是 `comment.yourdomain` 和 `_railway-verify.comment.yourdomain`），点击 `Update` 并等待修改在全球各大服务器生效，一段时间后验证便会成功

4. 最后再回到 `_config.meow.yml` 填写：

   ```YAML
   waline:
     server_url: https://comment.yourdomain
   ```

   配置完成后，你可以进入 `https://comment.yourdomain/ui` 管理博客的评论。
